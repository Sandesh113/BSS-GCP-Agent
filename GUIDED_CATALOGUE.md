# Guided product creation

Open **Catalogue Studio → Create with Gemini** in the private Cloud Run UI. The product manager can type a full description or answer one question at a time. The microphone button records up to 30 seconds after the manager grants browser microphone permission. Press Stop to send the recording to the private Cloud Run service for Gemini transcription, review or edit the returned text, then press Send answer. The recording is not stored by the application. Typed input always works.

The assistant asks for the offering name, each currently service-backed leaf Product Specification, monthly and setup prices, and eligible customer segments. It asks only for missing details, then displays a review. **Save Draft product** creates one composite Product Specification and one Draft Product Offering. The product manager can inspect the new card and press **Publish offer**. Publication validates the catalogue mapping and makes the offering available in CPQ immediately; CPQ still checks compatibility, eligibility and price at quote time.

Gemini extracts a structured proposal from each answer. Python validates specification IDs, allowance amounts, prices, segments, catalogue version and PS-to-CFS references before saving. The model cannot create a CFS mapping or publish an offering itself. The Cloud Run service account has a custom IAM role containing only `aiplatform.endpoints.predict` for the model call. The configured model and EU endpoint can be changed through Terraform inputs.

The current executable catalogue has three service-backed leaf specifications: voice, data and SMS. The wider ten-specification/seven-CFS library in `catalogue_design/` remains a design reference and is not yet selectable in this runtime. A newly added leaf specification becomes available to the assistant only after a technical CFS mapping exists. New offers use the current CPQ fallback of a 12-month term unless the CPQ policy has explicit term rows; the assistant does not edit that policy.

Voice recording requires a browser that provides `getUserMedia` and `MediaRecorder`, a microphone, and permission for the site to use it. The server accepts only short audio in WebM, Ogg, MP4 or WAV, with a 2 MB limit, and sends it to the configured Gemini model over the same authenticated Vertex AI path as typed answers. If permission is denied or the microphone is unavailable, the page explains the issue and keeps typed input available. [Google documents](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/access-control) `aiplatform.endpoints.predict` as the permission for model prompt requests. The POC is TM Forum patterned and does not claim TMF620 conformance.

Verification: `tests/test_catalogue_assistant.py` checks guided Draft creation, dynamic questions, untrusted model output and stale catalogue versions. `eval/live_assistant.py` exercises the deployed Gemini → Draft → Publish → CPQ → ProductOrder path; its latest result is `eval/live_assistant_report.json`.
